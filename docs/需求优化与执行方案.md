# Banana Pro 需求优化与执行方案

## 一、现有网站 vs 需求文档的问题分析

### 1.1 核心问题

| 问题 | 说明 | 建议 |
|-----|------|------|
| **产品定位冲突** | 现有网站是"提示词宝库"（内容型），需求文档是"AI图像编辑器"（工具型） | 明确产品定位：主站做工具，prompts站保留并升级 |
| **MVP范围过大** | 需求文档包含批量处理、多模型切换等高级功能 | 精简MVP，核心功能优先 |
| **国际化过早** | MVP就要支持中英日三语 | 先中英，日文后续迭代 |
| **模型选择过多** | 6个模型选择导致用户决策困难 | 精简为2-3个核心模型 |
| **功能展示过多** | 6大功能导致用户认知负担 | 突出3个核心差异点 |

### 1.2 建议的需求调整

#### 原需求 → 优化后

| 原需求 | 优化后 | 理由 |
|--------|--------|------|
| 6个AI模型 | 3个核心模型 | 降低决策成本 |
| 批量处理（MVP） | 批量处理（V2） | 聚焦核心体验 |
| 三语言支持 | 双语言（中英） | 快速上线 |
| 6大功能展示 | 3大核心卖点 | 提升转化 |
| 单一网站 | 5个垂直网站 | SEO和流量最大化 |

## 二、产品定位优化

### 2.1 核心定位

**Banana Pro = AI图像生成工具垂直矩阵**

```
主站（工具）
    ├── 文生图
    ├── 图生图
    └── 角色一致性

垂直站（细分市场）
    ├── Anime - 动漫风格
    ├── Portrait - 肖像写实
    ├── Cyber - 赛博朋克
    └── Prompts - 提示词库
```

### 2.2 核心差异化（3个，非6个）

1. **自然语言编辑** - 无需学习复杂参数，像ChatGPT一样编辑图片
2. **角色一致性** - 同一角色在不同场景保持一致
3. **场景融合** - 一键更换背景，自然融合无违和感

## 三、MVP功能清单优化

### 3.1 MVP（第1版本）

**必须包含**:
- ✅ 文生图模式
- ✅ 图生图模式
- ✅ 2个核心模型（Banana Pro V2, Flux）
- ✅ 基础提示词输入（500字符）
- ✅ 图片上传（拖拽+点击）
- ✅ 结果展示和下载
- ✅ 3种预设风格（默认/动漫/写实）
- ✅ 移动端适配
- ✅ 中英双语

**不包含**（V2迭代）:
- ❌ 批量处理
- ❌ 多模型切换（6个）
- ❌ 高级参数控制
- ❌ 用户账户系统
- ❌ 支付功能
- ❌ 日文支持

### 3.2 功能优先级矩阵

| 功能 | 价值 | 难度 | 优先级 |
|-----|------|------|--------|
| 文生图 | 高 | 中 | P0 |
| 图生图 | 高 | 中 | P0 |
| 角色一致性 | 高 | 高 | P0 |
| 批量处理 | 中 | 低 | P1 |
| 用户系统 | 中 | 中 | P1 |
| 支付功能 | 高 | 低 | P1 |
| 日文支持 | 低 | 低 | P2 |
| 视频编辑 | 中 | 高 | P2 |

## 四、垂直网站快速上站方案

### 4.1 网站架构

```
banana-pro/
├── apps/
│   ├── main/              # 主站 - banana.ai

│   └── prompts/           # 提示词库 - prompt.banana.ai
├── packages/
│   ├── ui/                # 共享UI组件
│   ├── config/            # 配置系统
│   └── api/               # 共享API
```

### 4.2 各垂直站配置

|-----|------|---------|--------|---------|
| 主站 | banana.ai | AI image editor | #EAB308 | 1 |
| Prompts | prompt.banana.ai | AI提示词 | #10B981 | 2 |
| Anime | anime.banana.ai | anime AI generator | #FF6B9D | 3 |
| Portrait | portrait.banana.ai | portrait AI | #3B82F6 | 4 |
| Cyber | cyber.banana.ai | cyberpunk AI | #A855F7 | 5 |

### 4.3 配置驱动快速上站

每个垂直站只需一个配置文件：

```typescript
// apps/anime/config/site.config.ts
export default {
  name: "Anime AI Generator",
  tagline: "专注二次元AI绘画生成",
  domain: "anime.banana.ai",

  // SEO
  seo: {
    keywords: ["anime AI", "动漫生成", "二次元绘画"],
    primaryKeyword: "anime AI generator",
  },

  // 主题
  theme: {
    primary: "#FF6B9D",
    gradient: "from-pink-500 to-rose-500",
  },

  // 功能
  models: ["niji-journey", "anything-v5"],
  presets: ["anime-girl", "anime-boy", "manga-style"],

  // 内容
  navigation: [
    { label: "角色生成", href: "/characters" },
    { label: "场景生成", href: "/scenes" },
    { label: "提示词库", href: "/prompts" },
  ],
};
```

## 八、风险与缓解

### 8.1 风险评估

| 风险 | 影响 | 可能性 | 缓解措施 |
|-----|------|--------|---------|
| AI模型成本过高 | 高 | 中 | 分层定价 + 免费额度限制 |
| 竞争激烈 | 中 | 高 | 垂直差异化 + SEO优先 |
| 技术稳定性 | 高 | 中 | 多模型备份 + 错误处理 |
| 政策合规 | 中 | 低 | 内容审核系统 |

### 8.2 成本控制

**AI成本优化**:
- 免费版：10次/天（低成本模型）
- 付费版：无限（可切换高级模型）
- 图片缓存：复用生成结果

**基础设施成本**:
- Vercel免费额度足够起步
- Cloudflare R2存储成本低
- Supabase免费层可用
